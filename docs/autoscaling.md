# 动态节点自动扩缩容配置指南

本指南教您如何配置总控后台，让系统根据实时在线人数，自动购买/销毁云服务器，实现极致省钱。
**当前采用类似“游戏房间”实时分配，用户下线立刻腾出vps空余位置，vps理论利用率 95%+。**

---

## 一、 核心机制

每台动态 VPS 就是一个**“游戏房间”**，容量上限由“最大在线人数”决定。
* **只看当前在线**：系统只看当前房间里有多少用户。没达标就不扩容。
* **固定垫底**：优先分配已有vps，不够了再自动去云商买新vps开房。

---

## 二、 什么时候扩容和缩容？

* **扩容**：某地区vps快满了 -> 立刻去云服务商买新vps -> 开新vps。
* **缩容**：某地区用户太少 -> 挑快到期且没人的vps -> 把剩下的人平滑移走 -> 退房销毁。

---

## 三、 后台参数怎么填？（核心配置）

去 **系统设置 -> 动态扩缩** 页面，各项参数对照以下说明进行填写：

| 参数名称 | 推荐默认值 | 这参数是什么意思？该怎么填？                            |
| :--- | :--- |:------------------------------------------|
| **检测间隔** | `30 秒` | -                                         |
| **单 VPS 最大在线人数** | `10 人` | 一个vps最多允许多少人同时在线。                         |
| **最小动态 VPS 数** | `0` | 每个地区最少保底留几个vps。填 0 就是没人的时候全关闭。            |
| **最大动态 VPS 数** | `10` | 每个地区最多只能开几个vps。                           |
| **扩容触发阈值** | `90%` | vps在线率>=90%，就去买新vps。                       |
| **缩容触发阈值** | `30%` | vps在线率<=30%，就关闭                           |
| **缩容持续时间** | `300 秒` | vps空了之后，观察多久才真关闭。防止晚高峰用户短暂掉线误关闭。          |
| **冷却时间** | `120 秒` | 买完一台新vps，强制休息 2 分钟。防止瞬间买入过多vps。            |
| **计费周期** | `60分钟` | 云商多久扣一次费（通常按小时）。                          |
| **提前销毁缓冲** | `5 分钟` | 比如 15:00 扣费，系统会在 14:55 把空vps退掉，避免多扣一小时的钱。 |

---

## 四、 调度模式（按时段营业）

您可以配置vps只在人多的时候开，没人的时候退掉。

* **全天候模式**：24 小时监控并扩缩容。
* **指定时段模式**：比如只填 `18:00-23:00`（晚高峰）。
  * 在这个时段内，系统正常自动扩容。
  * 过了这个时段，系统停止扩容，并逐步退回所有vps，只保留“最小动态 VPS 数”。
* **时区说明**：基于 VPS vps所在的本地时区执行。

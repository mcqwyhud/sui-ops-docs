# 账号共享控制系统配置指南

本指南教您如何防止用户把一个账号买给几十个人“合租”使用，保护您的带宽不被恶意消耗。

---

## 一、 核心原则（必读）
开启防共享功能后，**强烈建议先不要开启“自动封禁”**。
您可以先运行几天，观察后台的用户“风险分”记录，摸索出一个不会误伤正常用户，又能卡死合租党的数值，然后再开自动封禁。

---

## 二、 总控参数怎么调？（系统设置 -> 账号共享控制）

### 1. 基础开关
* **启用风险控制**：打开后，系统开始给用户的行为打分。
* **自动封禁**：打开后，分数达标系统直接封号。

### 2. 行为打分规则（怎么加分？）
* **同时多节点在线**：用户同一时间在两个节点都有流量，加分。
* **频繁切节点**：比如 60 秒内连续切换了 3 次以上，狂加分。
* **清分机制（衰减）**：犯错的分数不会跟一辈子，随着时间推移会自动降低。推荐值 0.6 - 0.85。

### 3. 阈值怎么设？
* **警告线（默认 60 分）**：到了这个分，系统悄悄记录一下，不影响用户。
* **封禁线（默认 90 分）**：到了这个分，直接强制下线。

---

## 三、 节点参数怎么调？（修改 nodeRisk.json）

如果总控的全局规则不够用，您可以用 Root 登录单台 VPS，修改底层的 `nodeRisk.json` 文件。这个文件决定了这台机器具体怎么判断“合租”。

文件里各项参数的意思如下：

**1. 基础开关**
*   `"enable"`：**总开关**。`true` 为开启防共享，`false` 为关闭（如果您把这台机器单独分配给企业大户，就改成 `false`）。

**2. 时间窗口**
*   `"windowMs"`：**统计时间窗口**（单位：毫秒）。默认 `10000`（也就是 10 秒）。系统只抓取这 10 秒内的行为来打分。

**3. IP 数量限制（抓异地多拨）**
*   `"ipWarn"`：**警告线**。默认 `3`。同一个账号在 10 秒内出现了 3 个不同 IP，开始扣分。
*   `"ipLimit"`：**封禁线**。默认 `6`。出现了 6 个不同 IP，直接狂扣分。

**4. 设备连接数限制（抓多设备合租）**
*   `"connWarn"`：**警告线**。默认 `10`。同一个账号在这台机器上同时有 10 个连接，开始扣分。
*   `"connLimit"`：**封禁线**。默认 `25`。同时有 25 个连接，狂扣分。

**5. 突发高并发惩罚**
*   `"burstConnThreshold"`：突发连接阈值。默认 `8`。
*   `"burstIpThreshold"`：突发 IP 阈值。默认 `3`。
*   `"burstWeight"`：**突发惩罚分**。默认 `25`。如果连接数瞬间超过 8 个，且 IP 超过 3 个（这极其像机场软路由或分享），直接猛加 25 分！

**6. 分数缩放**
*   `"finalScale"`：**最终分数放大器**。默认 `1.0`。如果设为 `1.2`，所有的扣分都会乘以 1.2（更容易封号）；如果设为 `0.8`，扣分变缓（更宽松）。

**7. 协议权重（防误判）**
*   `"protocolWeights"`：不同协议的敏感度。
  *   比如 `hysteria2`（默认 1.5）或 `tuic`（默认 1.7），因为 UDP 协议本身就会产生大量并发连接，所以默认惩罚更重。
  *   如果您发现某个节点用 `hysteria2` 的用户全被误封了，就把该协议的数值下调（比如改成 `1.0`），让它跟普通 TCP 协议一样宽松。

**完整的参数文件长这样：**
```json
{
"enable" : true,
"windowMs" : 10000,
"ipWeight" : 10.0,
"ipWarn" : 3,
"ipLimit" : 6,
"connWeight" : 1.0,
"connWarn" : 10,
"connLimit" : 25,
"burstWeight" : 25.0,
"burstConnThreshold" : 8,
"burstIpThreshold" : 3,
"finalScale" : 1.0,
"protocolWeights" : {
"wg" : 1.2,
"hysteria2" : 1.5,
"trojan" : 1.0,
"wireguard" : 1.2,
"shadowsocks" : 1.0,
"tuic" : 1.7,
"vless" : 1.0,
"vmess" : 1.0
},
"defaultProtocolWeight" : 1.0
}
```
*(注意：`ipWeight` 和 `connWeight` 是底层打分的基础权重，一般不需要动，调 `Warn` 和 `Limit` 就可以了)*

## 四、 常见问题解答 (FAQ)

**Q1：用户频繁切换节点会触发封禁吗？**
* **解答**：不会。单次切换只给总控追加 5 分，即使连续切 3 次也只额外追加 8 分，过几分钟分数就自动清零了，离 90 分的封禁线差得很远。

**Q2：手机移动网络 IP 频繁变动会触发封禁吗？**
* **解答**：不会。系统底层逻辑是：必须同时出现 3 个及以上不同 IP，且多个节点并发才会高分。手机基站切换导致的正常 IP 变动不会受罚。

**Q3：同一个账号多个设备同时使用会触发封禁吗？**
* **解答**：如果多设备连的是同一个节点，不算违规；但如果多设备连了不同的节点（比如异地合租），系统每次检查都会抓到，分数会越堆越高，最终必定封禁。

**Q4：如果某个套餐或大代理被误封了，该怎么调整？**
* **解答**：如果他是企业大户，不要为了他去调低全站的风控。请给他单独开一台 VPS，把那台机器配置文件里的 `"enable"` 改为 `false` 关闭风控，让他去连那台机器。

**Q5：如果普通节点（正常用户核心池）发生大面积误封该怎么办？**
* **解答**：说明当前的封禁线卡得太死。
  1. 去总控后台，把 **封禁线** 上调（比如调到 100 分），把 **风险衰减系数** 调低（比如 0.6），让分数流失得更快。
  2. 或者登录异常节点的 VPS，把 `ipWarn`（默认3）和 `connWarn`（默认10）调高，让计分门槛更宽松。
